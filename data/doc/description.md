Необходимо создать структуру таблиц для системы складского учета. Основные требования:
 - при регистрации мерчанта (таблица user) создается кабинет складского учета даллее будем называть его просто кабинет
 - каждый зарегистрированных пользователь получает доступ к своему личному кабинету
 - может добавлять сотрудников в своём кабинете, сотрудники не могут иметь доступ к разным кабинетам
 - все таблицы должны быть связаны с кабинетом по уникальному ключу 
 - Уникальный ключ у всех таблиц должен быть в едином формате `uuid` binary(16) NOT NULL
 - у каждой таблицы должно быть поле created_at (метка времени создания записи) и updated_at (метка времени обновления записи)
 - перваначальная структура базы данных представлена в файле current_structure.sql
 - таблица Номенклатура. которая имеет поля: название, тип, единица измерения, артикул, производитель.
 - таблица остатков. По сути это составная таблица состоящая из полей: id номенклатуры, id склада в который был сделан первичный приход остатка, цена прихода на склад.
 - Склад имеет основные параметры такие как: название, тип, идентификатор.
 - Таблица движение остатков это по сути история остатков в которой фиксируется дата и время документа, номер документа, цена прихода или цена расхода, id операции, тип операции (приход = 1 или расход = 2 из таблицы операций), оригинальная цена товара, скидка, ставка НДС, сумма НДС
 - Таблица складских операций это название операции (приход, расход, движение товара на складах, возврат, списание и т.д.) тип операции (приход=1 или расход=2)
 - Таблица цен продажи номенклатурных остатков, содержит поля: идентификатор номенклатуры(связан с таблицей номенклатур), название прайс листа, оригинальная цена продажи, дата начала действия цены, дата окончания действия цены продажи (по умолчанию null), скидка на товар, сумма с учетом скидки, ставка НДС, сумма НДС.
